## Current Baseline

The exact layer-on 2.39 run reaches a native 32-byte FAT long-filename write
for `uiv2.txt` whose HCC cache calculation underflows to unmapped
`0x0f676e34`. The compact OTA fragment is not a coherent writable filesystem.
The firmware reference environment demonstrates that intercepting the public
file wrapper preserves native-created data while existing reads continue
through the OTA-backed implementation.

## Implementation

Extend `sapporo-2.39-synthetic-wbsto` with one hit-bounded logical-file
intervention. On an observed enum-mode create for an allowlisted path, return
a bounded opaque handle and retain subsequent close/tell/truncate/seek/write/
read/flush effects in machine-owned memory. Mode-two reopen preserves the
existing file; read/update opens only bind an already-created logical file.
Missing read-only files fall through to native storage. Validate complete
guest ranges, arithmetic, mode, handle, path, file ceiling, and hit budget
before any mutation. Unknown create paths and any operation on a stale or
synthetic-range unknown handle refuse compatibility.

Snapshot serialization is explicit little-endian and validates the full
logical state before replacing it. It stores no source firmware or filesystem
bytes—only native bytes generated during the current session.

## Handoff

Implemented a machine-owned logical-file adapter on the exact Sapporo 2.39
public wrapper ABI. It accepts only enum modes 1–3 and the eleven evidenced
paths and capacities, passes missing read/update files through to the native
filesystem, and retains only bytes written by the guest. All path, guest-range,
arithmetic, capacity, handle, and intervention-budget checks complete before
mutation. Cold reset clears the adapter, software reset preserves it, and the
state is appended only to the exact layer's existing machine snapshot section;
older two-intervention layer snapshots restore an empty adapter.

Focused unit, compatibility, profile, and machine-snapshot tests pass, as do
`make check-lines`, `make check`, focused ASan/UBSan, and the exact private
firmware runner. Two layer-on logs and snapshots are byte-identical (log
SHA-256 `82fe5769ed4c6d886a8adca29ac4cda61b5a7b8bc1e63045ca42c26bd4fcb5b9`;
snapshot `d3f7d317553d689ca7595631a84193d788c4cc95563acbefeaeb241aa9364024`).
The run records 118 logical-file operations and retains `settings/sync.txt`
at 0 bytes, `settings/uiv2.txt` at 235, and `settings/general` at 1505, while
the prior `0x0f676e34` FAT underflow remains absent. Snapshot resume executes
the next instruction identically and enters the newly isolated reset.

That next boundary is a precise HardFault on IOM2 address `0x40052120`, with
stacked PC `0x0014e8ee` and command state matching the read-only reference's
I2C address-`0x5c` probe. It requires a separate evidence-gated IOM2/pressure
transaction ticket. No generic acknowledgement or sensor response is
authorized by this work.
